What it catches

Four kinds of fraud, in plain words

⚡

Too fast

More than 5 payments on one card within a minute. People don't shop that fast; bots do.

🔍

Card testing

Several tiny payments at different shops. Criminals check whether a stolen card works before using it.

💳

Over the limit

A payment that would push the card past its daily spending limit.

✈️

Impossible travel

Used in Berlin, then in São Paulo four minutes later. No one travels that fast.

Why Kafka Streams

The answer is already waiting

Most systems look things up in a database for every payment. That's slow, and if the database struggles, fraud checks stop. This engine keeps what it needs in memory, updated as each payment flows in, so the answer is ready before the question is asked.

The usual way

payment→database lookup→answer

A heavy query on every payment, and the database is a single point of failure.

This project

payment→memory, already up to date→answer

A local read. The state can be rebuilt from Kafka at any time.
